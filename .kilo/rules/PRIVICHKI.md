## Обязательные правила поведения

### Git

- **Автор коммитов ВСЕГДА `Vegass / dmitriy@vegass.dev`.** Без флагов `-c user.name=...`
  коммит уйдёт от `Dim41g / ivanov1331d@gmail.com` (твой локальный `~/.gitconfig`),
  и история авторства ломается.
- **Команда коммита:**
  ```bash
  git -c user.name=Vegass -c user.email=dmitriy@vegass.dev commit -am "..."
  ```
- **`git push origin main`** — только после явного "ок" пользователя. Не пушить самовольно.
- Приватные ключи (`id_ed25519_*` без `.pub`) НЕ коммитить, не логировать,
  не вставлять в `docs/*.md`. Публичный ключ — безопасен для документов
  (например, для recovery-инструкции через Contabo rescue-mode).

### Серверные операции

- Все SSH-команды — через алиас `ssh privichki-prod` (ed25519 ключ
  `~/.ssh/id_ed25519_privichki`, настроен в `~/.ssh/config`).
- `sshpass` НЕ используется. Пароль root не хранится в проекте и не
  применяется для обычного входа.
- **Не править `/app` на сервере напрямую** — теряется при следующем rsync.
- **Не использовать `docker compose down`** без явного ок.
- Все деплои — через `infra/deploy.sh` или ручной `rsync → /tmp/privichki_new → /app/apps/X → docker compose build X --no-cache → up -d X`.

### Стиль кода

- **Backend:** `api → services → repositories → models`. Сервисы НЕ вызывают
  `session.commit()` (исключение — admin endpoint `/admin/v1/habits`, помечен
  комментарием).
- **Деньги — `int` копейки.** Никогда `float`/`Decimal` для `deposit_balance`,
  `penalty_amount`, `prize_pool`, `amount`. Грепнуть `rg "Decimal\\(|float\\("` перед merge.
- **`user_id`** — только из `request.state.telegram_user` (после initData-валидации).
  Никогда параметром запроса.
- **Async I/O** везде. `aiohttp`, `asyncpg`, `asyncio.sleep`, `asyncio.to_thread`.
- **DI через конструктор.** Никаких глобальных мутабельных состояний.
- **Celery `send_task` по имени** (`apps/backend/app/services/celery_producer.py`).
  Backend НЕ импортирует worker-модули (`include=[]`).
- **Доменные исключения** в `core/exceptions.py`, глобальный handler в `main.py`.
- **Frontend:** данные через хуки над `shared/api`. Никакого `fetch`/`axios` в компонентах.
- **PII:** НЕ логировать `first_name`, `username`. Только `user_id` (числовой).
- **TypeScript:** `any` — только с обоснованием.

## Ритуал поддержания доков в актуальном состоянии

> **Главное правило проекта.** Документы устаревают, если их не обновлять вместе
> с кодом. Подробности — `docs/AGENT_BOOTSTRAP.md` §12. Краткий алгоритм:

**После каждой успешной задачи** ("всё работает"):

1. Определи, какие `docs/*.md`, `AGENTS.md`, `apps/frontend/docs/STATUS.md`,
   `.kilo/skills/habit-club-dev/SKILL.md` затрагивает изменение.
2. Сверь их с реальным кодом/сервером:
   - Версии пакетов (`requirements.txt`, `package.json`)
   - Имена файлов/тасок/функций
   - Схема таблиц (`apps/backend/app/models/`)
   - Список эндпоинтов (`apps/backend/app/api/`)
   - Состояние БД (`SELECT count(*) FROM ...`)
3. Если расхождения есть — точечная правка с snapshot-меткой `> Snapshot от YYYY-MM-DD`
   или `⚠️ Расхождение с реальностью`.
4. Если расхождений нет — сообщи что проверил, ничего не правил.
5. Коммить и пушить — `git -c user.name=Vegass -c user.email=dmitriy@vegass.dev ...`,
   push только после "ок".

**Анти-паттерны:**
- ❌ "Доки надо обновить, но я не буду" — нарушение ритуала.
- ❌ Правки доков в одном коммите с feature-кодом.
- ❌ "Это не моя задача" — поддержание доков это часть задачи.
